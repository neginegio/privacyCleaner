# PDF作業状態の一時保存設計

## 目的

31ページ以上のPDF確認作業を途中再開できるようにする。ただし、元の個人情報、OCR全文、未加工の検出文字列を平文保存しない。

## 保存対象

- 入力PDFのファイル指紋: SHA-256、ファイルサイズ、更新日時
- ページ状態: ページ番号、ページ種別、品質判定、確認済みフラグ、警告コード
- 候補状態: 候補ID、情報種別、確定状態、匿名化範囲、変換後文字列、結合元ID
- 手動範囲: ページ番号、矩形座標、情報種別、変換後文字列
- UI状態: 最後に開いていたページ、選択中候補ID

## 保存しない情報

- OCR全文
- 元の検出文字列
- PDF本文の抜粋
- 画像切り出し
- 出力Excel/PDF内に仮名対応表

## 候補ID

候補IDは、次をHMAC-SHA256で作る。

- 秘密鍵
- 入力PDF指紋
- ページ番号
- 正規化済み候補文字列
- 情報種別
- 座標

単純なハッシュではなく秘密鍵付きHMACを使うことで、保存ファイルだけから元文字列を辞書照合しにくくする。

## 保存形式

JSONを基本形式とし、保存時に暗号化する。

- 開発時: アプリ内の一時鍵またはユーザー指定パスフレーズから導出した鍵
- Windows配布時: DPAPIまたはユーザー指定パスフレーズから導出したAES-GCM鍵
- 保存先: 出力PDFとは別の作業状態フォルダ

## 削除方法

- PDF出力成功後、利用者へ作業状態を削除するか確認する
- 「このファイル内だけ」の処理では既定で削除する
- 削除時は通常削除を行う。SSD環境では完全消去を保証できないため、報告書へ明記する

## 再読込時の検証

- 入力PDFのSHA-256、サイズ、更新日時が一致するか確認する
- 一致しない場合は再開せず、再スキャンを促す
- 復元した候補IDと現在スキャン結果の候補IDが一致しない場合、その候補はREVIEW_REQUIREDへ戻す

## 今回の実装範囲

この設計は一時保存機能の方針を固定するためのもの。現時点では、平文で危険な状態保存を入れず、画面内のページ移動中に状態が失われないことを先に実装する。
