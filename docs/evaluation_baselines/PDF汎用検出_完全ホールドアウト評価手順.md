# PDF汎用検出 完全ホールドアウト評価手順

この手順は、Generation3以降の候補生成ルールを変更せず、まったく未使用のPDFに対して最初の1回だけ評価するためのものです。

## 前提

- 評価対象PDFは、過去のルール開発、原因分析、レビュー、OCR品質評価に使用していないものに限定する。
- 評価完了まで候補生成ルールを変更しない。
- 正解データ、レビュー状態、候補生成結果、OCR全文、座標情報を候補生成コードへ渡さない。
- 個人名、会社名、原文、OCR文字列、正解文字列、正解座標、HMAC値、秘密鍵をGit管理ファイルへ保存しない。

## 手順

1. 新しいPDFを完全ホールドアウト評価対象として固定する。
2. Generation3のコードを変更せず、候補生成を1回だけ実行する。
3. 初回候補結果、ページ品質、候補数、ルール別候補数を `ocr_quality_outputs` に保存する。
4. その後、ユーザーが専用レビュー画面で正解データを作成する。
5. 正解データ確定後、初回候補結果と正解データを比較する。
6. `ground_truth_count`、`candidate_count`、`matched_ground_truth_count`、`missed_ground_truth_count`、`true_positive_candidate_count`、`false_positive_candidate_count`、`recall`、`candidate_precision`、`average_coverage`、`minimum_coverage` を算出する。
7. 評価終了まで候補生成ルールを変更しない。
8. 評価結果を記録した後、改善が必要な場合は別ブランチまたは別作業として開始する。

## 禁止事項

- 正解CSV、正解JSON、truth_id、正解座標、正解文字列を候補生成に使用すること。
- 固定ページ番号、固定座標、特定会社名、特定個人名に依存する候補生成を追加すること。
- 初回候補結果を見てから、同じPDFの評価前に検出ルールを調整すること。
- この31ページPDFを完全ホールドアウト、未知データ、最終汎化性能評価に再利用すること。
